# AI Football Lab V10

**Global Multisport Intelligence** — статическая аналитическая система для GitHub Pages, которая сначала независимо моделирует возможный результат спортивного события, а затем сравнивает рассчитанные вероятности с реальными букмекерскими рынками.

Проект не обещает выигрыш, не использует реальные денежные средства и не является финансовой рекомендацией. Виртуальный банк применяется только для проверки качества модели.

## Концепция 15 → 4

Каждый день система:

1. Закрывает завершённые прогнозы и обновляет виртуальный банк.
2. Получает глобальный календарь футбола и хоккея.
3. Сначала анализирует футбол; хоккей заполняет недостающие места.
4. Строит распределение вероятных результатов каждого события.
5. Рассчитывает исходы, тоталы, форы и доступные дополнительные рынки.
6. Публикует до 15 полноценных аналитических прогнозов.
7. Выбирает до 4 квалифицированных лучших ставок.
8. Фиксирует по 20% текущего виртуального банка на каждую лучшую ставку.
9. Сохраняет историю, калибровку и ошибки модели.

Система не обязана публиковать четыре ставки. Слабый вариант не добавляется только ради заполнения места.

## Основные источники

### The Odds API — обязательный

Используется для:

- глобального списка активных видов спорта и лиг;
- календаря событий;
- реальных коэффициентов нескольких букмекеров;
- рынков `h2h`, `spreads`, `totals`;
- дополнительных футбольных рынков, когда они реально доступны;
- завершённых результатов;
- контроля израсходованной квоты.

Секрет GitHub:

```text
ODDS_API_KEY
```

### football-data.org — необязательный, но рекомендуемый

Добавляет историю и форму команд для поддерживаемых футбольных соревнований. События без покрытия не выдумываются: они получают прозрачный уровень данных `MARKET` или `HYBRID`.

```text
FOOTBALL_DATA_API_KEY
```

### NHL public API — без ключа

Для NHL подключается публичная таблица команд. Результаты и букмекерские линии остаются привязаны к The Odds API.

### OpenRouter — необязательный

Используется только для краткого объяснения уже рассчитанных числовых выводов. OpenRouter не создаёт коэффициенты и не заменяет математическую модель.

```text
OPENROUTER_API_KEY
```

Необязательная переменная:

```text
OPENROUTER_MODEL
```

## Уровни качества данных

- `FULL` — расширенная статистика и рыночные данные.
- `HYBRID` — доступная статистика плюс рыночный консенсус.
- `MARKET` — безмаржинальный консенсус нескольких букмекеров и модель, восстановленная из рынка.

Уровень показывается на сайте и влияет на уверенность и квалификацию лучшей ставки.

## Анализируемые рынки

Базовые рынки:

- победа хозяев, ничья, победа гостей;
- форы;
- тоталы.

Дополнительные футбольные рынки запрашиваются выборочно при наличии квоты и поддержки события:

- обе забьют;
- ставка без ничьей;
- двойной шанс;
- индивидуальные тоталы;
- альтернативные форы и тоталы.

Публикуется только реальный рынок с реальным коэффициентом минимум двух букмекеров.

## Обучение на результатах

После завершения событий система обновляет:

- Brier Score и Log Loss;
- калибровку вероятностей;
- точность по спорту;
- точность по лиге;
- точность по типу рынка;
- точность по диапазону коэффициентов;
- прибыль и просадку виртуального банка.

Корректировка вероятности начинается только после минимального количества завершённых наблюдений. Один проигрыш не переключает стратегию автоматически.

## Виртуальный банк

- только `bestBets` изменяют банк;
- каждая новая ставка равна 20% текущего банка;
- максимум четыре активные ставки в публичном блоке;
- коэффициент фиксируется при публикации;
- выигрыш, проигрыш и возврат рассчитываются после официального результата;
- все 15 прогнозов используются для обучения, но не создают финансовую экспозицию.

## Автоматическое обновление

Workflow `.github/workflows/update-data.yml` запускается каждые три часа.

- До установленного времени ежедневной генерации выполняется только проверка результатов.
- Новый список формируется один раз за локальную дату или вручную.
- Завершённые матчи закрываются в течение дня.
- При временной ошибке отдельного источника сохраняется последний корректный публичный state.
- GitHub Pages получает обновлённый JSON после автоматического commit.
- Браузер проверяет `data/state.json` каждую минуту без полной перезагрузки страницы.

Ручной запуск поддерживает параметр `force_generation`, который принудительно формирует новый список дня.

## Локальная проверка

```bash
python -m py_compile scripts/update_predictions.py
python scripts/update_predictions.py --validate
python scripts/update_predictions.py --self-test
node --check assets/app.js
```

Миграция старого состояния без сброса виртуального банка:

```bash
python scripts/update_predictions.py --migrate-state
```

Принудительное production-обновление требует `ODDS_API_KEY`:

```bash
python scripts/update_predictions.py --update
```

## Файлы данных

- `data/state.json` — публичное состояние сайта, банк, 15 прогнозов, лучшие ставки, история и обучение.
- `data/ai_daily_analysis.json` — компактный ежедневный снимок.
- `data/last-update-report.json` — диагностика последнего запуска и квоты.

## Ограничения

Наличие коэффициента не означает, что событие прогнозируется надёжно. Покрытие составов, травм, xG и расширенной статистики зависит от подключённых поставщиков. V10 не придумывает отсутствующие сведения и снижает уровень качества данных.

Фраза «повышенная рыночная аномальность» означает только статистический сигнал. Она не является утверждением о договорном характере матча.
